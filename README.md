## How I Usually Judge a Need

我看一个需求，通常不会先问要做什么功能，而是先看这件事到底在解决什么问题。

很多时候，被提出来的是一个方案，但背后真正的问题并不在那个方案本身。我会先往回看一层，看看问题究竟出在哪，谁在承担成本，哪个环节在重复损耗，为什么这件事现在必须被提出来。

然后再继续判断几件事:

- 这是不是一个真实存在、会持续发生的问题
- 它影响的是局部体验，还是更大的业务效率和服务质量
- 这件事如果不处理，后面会不会持续放大
- 现在做是不是合适，还是应该先解决别的问题

很多复杂项目到了最后，真正决定结果的不是功能多少，而是最开始有没有把问题看准、把边界看清、把优先级排对。我一直比较重视这种基于问题本质的判断方式。

## How I Usually Move Work Forward

在推进复杂项目时，我通常会先把目标、边界、阶段和判断标准说清楚，再抓关键矛盾，组织跨团队协同。很多项目推进困难，并不是因为执行不够努力，而是前面的问题没有被定义清楚。

我比较在意的，也不只是把一件事交付出去，而是做完之后有没有留下方法、标准、评价体系和可复用的结构。对我来说，项目的价值不只在当下结果，也在于它能不能沉淀成长期能力。

## Perspective

我一直认为，在数字医疗和健康科技领域，服务从来不是单一模块的结果，而是内容、产品、运营、资源和组织协同之后的结果。

这也是为什么我会同时重视内容质量、用户体验、服务链路、产品测评和实际使用感受，而不会只看某个功能有没有做出来。

在新能力的应用上，我保持开放，但也比较克制。我关注 AI 医疗大模型、AI 问诊、Prompt 设计与调优，也持续在看这些能力怎样进入真实场景。但我更看重的，始终是它是否符合医疗一致性、医疗安全和伦理道德的要求，是否真的能给用户、服务方和业务带来正向价值。

就是围绕女性健康、母婴健康与数字医疗相关服务，去处理那些既复杂、又具体，既需要业务判断，也需要项目推进，既要考虑用户体验，也要考虑服务结果的事情。

我更在意的，从来不是把一件事说得多新，而是把它真正做成、做稳，做成一个可以长期运转的业务、服务体系或能力。
